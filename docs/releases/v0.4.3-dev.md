## What's Changed

- New bundled plugin: Denoise (profiled). It models the sensor noise as
  `V(X) = a * X + b`, stabilizes that variance with the generalized Anscombe
  transform, and shrinks the result with edge-aware a-trous wavelets, which is
  what darktable's _denoise (profiled)_ does in its wavelets mode
- The host reads the camera and the ISO setting out of a RAW file and fills the
  noise model of that plugin from the camera's profile, the way darktable does,
  interpolating between the two neighbouring ISO settings when the database has
  no shot for the exact one. The profile database is a copy of darktable's
  `data/noiseprofiles.json`, which stays under darktable's GPL-3.0 license
  (`third_party/noiseprofiles`)
- The host now reports the proxy render scale of a preview or a draft pass to the
  plugins, so a denoiser follows the resolution it is handed: the preview shows
  the smoothing the export will write
- Linux: the AppImage carries update information, so AppImageUpdate and
  `appimageupdatetool` update it in place instead of asking you to download the
  whole file again
- Linux: a build from a `release/vX.X.X` branch follows the pre-release list and a
  stable build follows the newest stable release, so neither is ever offered a
  build older than itself
- Linux: the release publishes the `.zsync` file that those tools read. The file
  sits beside the AppImage and records the SHA-1 of that AppImage, so an update is
  verified against the build it replaces
- Linux: an AppImage downloaded before this release carries no update
  information, so download this build once to start receiving in-place updates
- Packaging: the appimagetool that builds the AppImage is pinned to release 1.9.1
  and checked against its published SHA-256
- README: the Linux section names the update command and its trust model, and the
  Windows example passes the version label that the build reads
- Packaging: the self-test is its own executable, so it needs no window and can run
  on a machine without OpenGL. The macOS bundle and the AppImage carry it beside
  the host, and `OfxRawHost --selftest` still runs it; the single-file Windows
  build keeps it inside the executable
